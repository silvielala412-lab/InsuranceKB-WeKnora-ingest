## 先说结论

九款产品、27 份 PDF、399 页都跑完了，六类险种都能在同一个页面里切换查看。
九款“险种简称”全部抽到，并且都能定位到保险条款第一页。

本轮排除外部映射、人工填充和纯 LLM 总结字段后，共有 458 个可自动抽取字段：

| 口径 | 结果 | 说明 |
|---|---:|---|
| 字段有值率 | 237/458 = **51.7%** | 只看 `present`，分母包含材料本身不具备的字段 |
| 已形成结论 | (237+63)/458 = **65.5%** | `present + absent_explicitly`，不等于抽取准确率 |
| 当前材料支持条件下抽取率 | 237/324 = **73.1%** | 按 Schema 来源说明判断现有条款、说明书、费率表可能支持 |
| 候选页条件下抽取率 | 237/285 = **83.2%** | 只用于看“候选页已找到后，模型是否拿到值” |
| Evidence 已定位或归一化 | 417/508 = **82.1%** | 363 条精确定位，54 条归一化匹配 |

目前还不适合直接转向“完全不给 Schema”的实现。年金险和意外险仍有明显漏抽，
应先把候选召回和 Evidence 定位补齐，再把无 Schema 方案作为下一张独立任务卡研究。

## 与前三轮的可比结果

M139 为了在中断后的剩余预算内保证九款全覆盖，最终结果只跑了每款一次首轮抽取，
没有执行第二次定向补抽。因此只能把原三款放在一起比较：

| 运行 | 策略 | 原三款自动字段有值 |
|---|---|---:|
| M132 | 原项目基线 | 68/153 = 44.4% |
| M137 | LLM 语义裁决 + 两次机会 | 82/153 = 53.6% |
| M138 | 修复定向补抽合并 + 两次机会 | 86/153 = 56.2% |
| M139 | 九产品泛化测试，每款一次 | 80/153 = 52.3% |

M139 仍比 M132 高 7.9 个百分点，但比 M138 低 3.9 个百分点。主要原因是本轮没有
第二次定向补抽，加上 qwen-plus 本身有非确定性。这个结果证明当前策略能扩展到六类
险种，不证明九产品版本已经超过 M138 的双轮效果。

## 下一版怎么改

1. 缓存 PDF 逐页解析结果。同一批 399 页本地重复解析耗时明显，不应每次运行重做。
2. 调用预算先为每款保留一次首轮，再按 `candidate_found + unknown` 数量分配补抽，避免
   前面的产品耗尽预算，后面的产品只能缺席。
3. 年金险不能只靠通用关键词。按责任、领取、账户、分红、保全几个字段组分别做语义
   候选扫描，每组让字段与全部页面做一次相似度排序。
4. 对 Evidence 未定位较多的意外险，先保存模型 quote 周边文本，再做归一化、跨行和表格
   单元格定位；保留值进入审核，不因定位失败清空。
5. 输出固定诊断原因：`material_unavailable`、`candidate_not_found`、
   `candidate_found_not_extracted`、`evidence_unresolved`，前端按原因展示待补字段。
6. 下一次固定同一九产品集，首轮与补抽分别计数；有专家 Golden 后再补准确率和召回率。

“不给 Schema”的后续方向仍可行，但建议走“模型发现草案 Schema -> 聚类去重 ->
Evidence 绑定 -> 人工/质量门确认 -> 版本化 SchemaPack -> 正式抽取”，不要让模型每次
临时发明一套字段直接进入知识库。
