## 这次改了什么

1. `coverage_summary` 增加责任语义锚点：保险责任、我们承担、给付、保险金、医疗
   费用、身故、满期、生存、重大疾病、意外等，不要求出现“保什么”标题。
2. 对全部页面先扫描，再按内容得分选择页面，并保留责任页面的相邻页面，覆盖跨页
   条件和限制。
3. 把专项上下文注入现有 Schema LLM 抽取请求，明确只汇总保险责任和核心给付；保单
   贷款、分红、自动垫交、减额交清、退保等由其他字段承接。
4. Evidence 暂时无法定位时保留已有字段值，标成待核验，不把值直接清空。
5. 增加任意文件名和文件顺序测试，确保没有针对 `产品说明书.pdf` 的特殊处理。

## 已知限制与下一步

第二轮重跑显示，单靠提示词仍可能把保全权益混入寿险的“保什么”。下一步建议增加
字段级语义校验：把保障责任、保全权益、分红权益拆成互斥标签，先让 LLM 给每个候选
责任打标签，再合并到对应 Schema 字段；不要用更多关键词继续堆叠。另一个待处理点是
跨行 OCR 文本导致部分长 Evidence 未定位，需要做段落级归一化和续接合并。

未定义 Schema 的动态发现流程本轮暂缓，记录在 M140 tasks 中。当前三款产品的
“适用人群”已经做过页级核验：596（产品说明书 p1、保险条款 p2/p24）、5003
（产品说明书 p1、保险条款 p1/p2）和 1826（产品说明书 p1/p5）都有年龄、投保
范围、产品目的或家庭/成人少儿描述，不能归为材料缺失；三款当前均为
`candidate_found_not_extracted`。后续应允许字段描述明确授权的有限语义汇总，
并把“材料缺失、候选未召回、候选已召回但未抽取、Evidence 未定位”分开计数。
