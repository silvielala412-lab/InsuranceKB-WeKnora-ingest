# 144 · 产品简介与产品概览内容总结补抽

## Goal

修复 Schema v5 中纯 `LLM生成` 的 `产品简介`、`产品概览` 只参加首轮大批量抽取、没有独立
补抽机会的问题。事实字段先抽取，内容字段再基于全材料和已抽取事实生成受限摘要。

## Owner

- 唯一写 Owner：当前总控 Codex
- 执行模型：`gpt-5.6-sol high`
- 本轮 provider：不调用外部模型，只做代码和本地测试

## Scope

- 新增纯 LLM 内容字段目标识别和一次内容总结补抽 pass；
- `产品简介`、`产品概览` 使用全 PDF 页面有序上下文，必要时按页保留有序摘要；
- 提供字段级提示，要求总结受材料约束，并绑定支撑性 Evidence；
- 与现有事实字段的 `present / absent_explicitly / unknown` 和 Evidence 合并合同兼容；
- 不改变材料支持抽取率分母，纯 LLM 字段仍不计入材料支持率。

## Requirements

- `M144-R1`：纯 `LLM生成` 的 `product_summary`、`product_overview` 在首轮结果为
  `unknown` 时必须进入内容总结目标集，不因 PDF 抽取资格过滤而跳过。
- `M144-R2`：内容总结目标使用产品全部 PDF 页面构造有序上下文；上下文受预算限制时，
  每页仍保留文档名、页码和有序片段。
- `M144-R3`：`产品简介` 和 `产品概览` 可以是基于原文的归纳文本，但必须提供支撑性逐字
  Evidence；不得添加材料之外的事实、承诺或数值。
- `M144-R4`：内容总结补抽不得覆盖已有更高质量事实字段；补抽返回 `unknown` 时保留
  首轮结果。
- `M144-R5`：无相关材料时保留 `unknown`，并记录原因；不得为了提高展示率硬填摘要。
- `M144-R6`：本轮只运行本地测试，不调用 provider，不写生产 DB，不进入 Candidate、
  Release、Active，不提交或推送 GitHub。

## Non-goals

- 不修改 Schema v5 工作簿或字段分类；
- 不把纯 LLM 内容字段纳入材料支持抽取率分母；
- 不改 Evidence 页码、来源身份和逐字校验规则；
- 不执行真实产品重跑或部署。

## Stop Conditions

- 需要新增 Schema 字段、修改生产审核策略或扩大到其它领域；
- 需要外部 provider 调用才能完成验收；
- 任何事实字段合并结果出现回退。
